# PERFORM ベータ版 — セットアップ・移行メモ（Phase 2：匿名化アーキテクチャ）

## 1. 今回の大きな変更：スプレッドシートを2つに分離

永代先生との議論（匿名化データ収集）とサシーム先生の方針を踏まえ、**スプレッドシートを本人情報用とデータ用の2つに分離**しました。

| スプレッドシート | 内容 | アクセス |
|---|---|---|
| **本人情報用**（IDENTITY） | 実名・メールアドレス・PIN・研究用背景情報（性別・専門医資格・PGY・経験件数など） | アクセス制限を強めに（石堂さん・管理者のみ推奨） |
| **データ用**（DATA） | 症例評価データ・コメント。実名は一切保存せず、匿名ラベル（学習者A、評価者1など）のみ保持 | 研究データとして共有・解析しやすい状態 |

**実名を知る必要があるのはアプリの画面表示だけ**（評価者は学習者の実名を見る、学習者は評価者の実名を見る、など）なので、アプリはその都度、本人情報スプレッドシートを参照して実名を解決する設計にしています。データ用スプレッドシートを直接開いても、実名は一切出てきません。

## 2. スプレッドシートの準備（2つ新規作成）

### ① 本人情報スプレッドシート
2枚のシートを作成し、1行目にヘッダーを入れてください。

**users**
```

```

**facilities**
```

```

2枚のシートを作成し、1行目にヘッダーを入れてください。

## 3. GASの設定

Code.gsの中身を新しいものに差し替えたら、上部の2つのIDを両方書き換えてください。

```js
const IDENTITY_SHEET_ID = 'YOUR_IDENTITY_SPREADSHEET_ID_HERE'; // ①本人情報スプレッドシートのID
const SHEET_ID           = 'YOUR_DATA_SPREADSHEET_ID_HERE';     // ②データスプレッドシートのID
```

デプロイの手順（新バージョンとして再デプロイ）はこれまでと同じです。

## 4. 匿名ラベルの仕組み

- **施設**：初めて登録された施設から順に「施設A」「施設B」…と自動採番（`facilities`シートで管理）
- **学習者**：施設ごとに「学習者A」「学習者B」…と自動採番
- **評価者**：施設ごとに「評価者1」「評価者2」…と自動採番

データスプレッドシートの`evaluations`・`comments`シートには、この匿名ラベルだけが保存されます。実名が必要な画面表示は、アプリがその都度、本人情報スプレッドシートを参照して解決します（評価者には引き続き学習者の実名が表示されます）。

## 5. ユーザー登録の運用変更

評価者（指導医）がpilot studyのワーキンググループのメンバーとなるため、**評価者がご自身と担当学習者の両方をまとめて登録する**運用にしました。

- `register.html`に「続けてもう一人登録する」ボタンを追加。1回のQRコードアクセスで、評価者→学習者A→学習者B…と連続登録できます
- 研究用の背景情報（性別・専門医資格の有無・卒後年数・対象術式の経験件数・指導医経験年数〔評価者のみ〕・自由記述）を登録時にあわせて収集
- QRコードを使わず直接アクセスした場合のために、登録コードの手入力欄も追加しました

## 6. 症例の術式について（サシーム先生の方針）

NCD術式との厳密な対応は今回は行わず、**各診療科の定型的な術式をいくつか候補として用意し、それ以外は自由入力**できるようにしました（`learner.html`の術式選択に「その他（自由入力）」を追加）。評価者が「どの術式か」を把握できれば十分、という位置づけです。

候補リストは以下の通り（たたき台なので調整可能です）。

- 消化器外科：腹腔鏡下胆嚢摘出術／腹腔鏡下虫垂切除術／腹腔鏡下結腸切除術／腹腔鏡下直腸切除術／腹腔鏡下胃切除術／鼠径ヘルニア修復術
- 産婦人科：腹腔鏡下子宮全摘術／腹腔鏡下卵巣嚢腫摘出術／帝王切開術
- 呼吸器外科：胸腔鏡下肺葉切除術／胸腔鏡下縦隔腫瘍摘出術
- 泌尿器科：腹腔鏡下（ロボット支援）前立腺全摘術／経尿道的膀胱腫瘍切除術（TURBT）
- 形成外科：遊離皮弁再建術／熱傷デブリードマン（仮。要確認）

## 7. 指導医評価の既読トラッキング（NEWバッジ）

永代先生からのご指摘（指導医評価を見たかどうかの検証データが欲しい）を受けて実装しました。

- 学習者の「結果」タブで、評価者からのフィードバックが未読の症例には赤い「NEW」バッジを表示
- 症例を開く（結果を閲覧する）と自動的に既読になり、バッジが消える
- データスプレッドシートの`evaluations`シートに`feedback_viewed_at`列を追加。既読になった日時が記録されるので、「見た／見ていない」「見るまでにかかった時間」を研究データとして分析できます

## 11. 今回の追加修正（4回目・共同研究者フィードバック対応）

共同研究者からの実機テストフィードバックを受けて、以下5点を反映しました。

- **症例ナンバリングを「施設×術式」→「学習者×術式」に変更**：`nextCaseNo()`を修正。これにより、各学習者から見て自分の症例が常にNo.1、No.2…と連続するようになりました。病院全体の症例数（時間軸情報）が症例番号から読み取れなくなる副次的な効果もあります
- **指導医画面のタブを「担当案件」「結果」の2つに整理**：旧「学習者別」タブを廃止し、「結果」タブの中で学習者ごとにグループ表示する形に統合しました。「担当案件」タブは未評価症例のみを表示するようにしています
- **画面レスポンスを改善**：表示名解決（`resolveName`）のたびに個人情報スプレッドシートを毎回開き直して全行読み込みしていたのが主な遅延要因でした。スプレッドシートオブジェクト・ユーザー一覧をリクエスト単位でキャッシュする仕組みを追加し、無駄な再読み込みをなくしました。GASが実行環境を使い回した場合に古いデータを引き継がないよう、リクエストの先頭でキャッシュを必ずリセットする安全策も入れています
- **術式選択を「診療科→術式」の2段階に変更**：まず診療科を選び、その診療科に紐づく術式リスト＋「その他（自由入力）」が表示される形にしました。診療科自体がリストにない場合の「その他（上記にない診療科）」にも対応しています
- **評価の一時保存機能を追加**：学習者・指導医どちらの評価入力画面にも「一時保存する」ボタンを追加しました。送信（ステータス変更・通知メール送信）とは独立した保存で、次回開いたときに入力内容が復元されます

**この更新でもデモデータの作り直しが必要です**（症例ナンバリング方式の変更に伴い、デモデータ内の症例番号を新方式に合わせて振り直しています）。`users`・`evaluations`・`comments`の3タブから`facility_code`が`DEMO`の行をすべて削除してから、Code.gs差し替え→`seedDemoData`再実行、の手順は変わりません。

- 学習者アカウントで同じ術式の症例を2件以上作成し、症例番号がその学習者の中で1から連番になることを確認
- 指導医画面で「担当案件」タブに未評価症例のみが表示され、「結果」タブで学習者ごとにグループ化された評価済み症例が確認できることを確認
- 学習者・指導医それぞれの評価入力中に「一時保存する」を押し、一旦別画面に移動してから同じ症例を開き直し、入力内容が保持されていることを確認（この時点では相手には通知が届きません）
- 診療科を選んでから術式候補が絞り込まれ、「その他」を選ぶと自由記入欄が出ることを確認
- 体感速度について、特に指導医の「結果」タブや学習者の「結果」一覧など、症例数が多い画面の表示が以前より速くなっているかを確認
